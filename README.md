# D-Fire YOLO11 — 화재 인식 & 합성 검증

> **D-Fire 데이터셋으로 화재를 학습한 YOLO11s가 합성 화재 데이터를 얼마나 인식하는가?** 그리고 그 인식을 어떻게 개선하는가의 과정.

**현재 상태**: 1·2단계 완료 · 3단계 우회 · 4단계(합성 방법론) 4.1\~4.3 완료 · 4.4(생성형)·5(실전 전이)는 프런티어/봉쇄. 팀 발표 시각자료 전달 완료.

핵심은 **정직한 프레이밍**이다 — 우리가 잰 것은 "프리즈 검출기가 합성을 *알아보나*"(프록시)이지 "실전 화재를 잘 잡나"가 아니다. 아래 [(A)/(B)](#a--b--정직한-프레이밍-핵심-방어선) 참조.

---

## 파이프라인 (6단계)

| # | 단계 | 상태 |
|---|---|---|
| 1 | Roboflow 공개 화재(D-Fire, 야외+실내)로 YOLO11s base 학습 | ✅ `ptrain_b79` · 정직 mAP50 **0.660** (recall 천장 0.894) |
| 2 | base로 합성(생성형) 검증 — recall 0.8 게이트 | ✅ 이미지 recall **0.809 ≥ 0.8 통과** → 4로 |
| 3 | 공개 + 합성 섞어 학습 | ⏭️ 우회 (2 통과) |
| 4 | **합성 방법론 (메인)** — 4.1 불꽃셋 · 4.2 합성법 · 4.3 aug/noise · 4.4 GAN/diffusion | ✅ 4.1\~4.3 · ⬜ 4.4 (선택) |
| 5 | 방법론 적용해 합성 생성 → 실전 전이 | ⛔ (B) 봉쇄 (실 급식실 화재 데이터 0) |

## 핵심 결과

- **base = 정직한 0.660** — 데이터 누수 제거 후 점수 (recall 천장 0.894).
- **합성 검증 통과** — 프리즈 base가 합성 유류불을 이미지 recall 0.809로 인식. 합성이 헛불을 유발하지도 않음 (ΔFP +0.030, CI가 0을 가로지름).
- **합성 방법론 ablation** (VFX 26장면 × 배경 18 × 크기 3 · rec@IoU0.5):
  - `over` 블렌딩 ≫ `screen` (1.55\~2.20×) — screen은 밝은 조리면에서 불꽃을 흰색으로 지움
  - 배치(랜덤 vs 조리면) 차이 없음 · 반사광은 소형에서만 도움 · **크기가 가장 큰 요인**
- **크기 한계** — 깨끗 + 충분크기(scale ≥ 0.25) recall **0.994**, 작으면(0.11) **0.694**로 붕괴.
- **낮은 recall의 정체 = 서로 다른 두 병목**:
  - @작은불 = **검출 병목** (실효 21px, base가 못 봄)
  - @큰불 = **위치 병목** (base가 밝은 코어만 tight 박싱 = D-Fire 관행·정상. 우리 GT가 헐거워 IoU가 낮게 나옴)
  - → **둘 다 우리 측정 설정 문제이고 가역.** base 결함 아님.
- **열화** — 조도 극단(저조도·과노출)이 지배적 killer, 순수 노이즈는 견고.

## (A) / (B) — 정직한 프레이밍 (핵심 방어선)

- **(A) 열려 있음** = 합성이 base 눈에 불로 보이나 (**프록시 · 필요조건**). 여기까지가 이 저장소가 한 일.
- **(B) 잠김** = 합성으로 *학습*시켜 *실전* 성능이 오르나. **진짜 급식실 화재 사진이 있어야 열림** (조리영상 28개 화재 0건 · AI-Hub 조리불 없음 = 봉쇄).

→ (A)의 합성 인식률이 (B)의 실전 성능을 대신하지 못한다. 발표·문서 전반에서 이 구분을 지킨다.
